# Feature request to issue

This skill is a shortcut. The procedure lives in the repository, so every tool
follows the same one.

1. From the repository root, read `docs/features.md` and follow it exactly.
2. The request is whatever the user wrote with this request, or the body of the
   `feature` issue they named. If there's neither, ask for the request in one
   sentence.
3. Open the issue even if the answer looks obvious, and even if you'd recommend
   declining. The record is the point.
4. Stop where `docs/features.md` stops: evaluation written, `needs-decision`
   added, the owner's call unmade. Report the issue and your recommendation.

If the request is about what the site _says_ rather than what the project
_offers_, it's a content idea: use `docs/agents/intake.md` instead.

If this file and `docs/features.md` ever disagree, `docs/features.md` wins.
